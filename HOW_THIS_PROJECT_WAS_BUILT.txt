1. THE PROBLEM & CORE CONCEPT
--------------------------------------------------------------------------------
In large university campuses like Sathyabama, visitors, freshers, and guest faculty 
often struggle to locate classrooms, labs, faculty cabins, and seminar halls across 
multi-storey buildings. GPS fails indoors because satellite signals cannot penetrate 
concrete slabs and walls.

To solve this, we built a digital twin of St. Paul's Block (CSE Department) paired 
with an intelligent indoor navigation engine that:
1. Calculates the mathematically shortest path using Dijkstra's algorithm.
2. Guides users visually in 3D across corridors and staircases.
3. Runs directly in any web browser via WebGL (no software installation needed for demos).
4. Has an Android ARCore mobile app for real camera-based AR tracking.

--------------------------------------------------------------------------------
2. SYSTEM ARCHITECTURE & DATA MODEL (THE MATHEMATICS)
--------------------------------------------------------------------------------
Before building any 3D graphics, we designed the core data model in pure C#:

A. Navigation Graph (G = (V, E)):
   - We modeled the entire building as a mathematical graph containing 32 nodes 
     and 36 bidirectional edges.
   - Each node (NavNode.cs) has:
     * Node ID (e.g., NODE_F0_ENTRANCE, NODE_F0_LAB1, NODE_F1_R101)
     * Real-world 3D coordinates in meters (X, Y, Z)
     * Floor ID (F0 = Ground, F1 = First, F2 = Second)
     * Node Type (Entrance, Waypoint, Destination, Staircase)
   - Coordinates match physical floor elevations:
     * Ground Floor (F0) : Y = 0.0 meters
     * First Floor (F1)  : Y = 4.0 meters
     * Second Floor (F2) : Y = 8.0 meters
     * Central corridor runs along the X-axis from X = 0m to X = 50m (Z = 0m).

B. Dijkstra's Shortest Path Algorithm (Pathfinder.cs):
   - Calculates the exact shortest route between any starting point and destination.
   - Operates in O((V + E) log V) time using a priority queue.
   - Edge weights represent true Euclidean physical distance in meters.
   - Handles multi-floor navigation seamlessly: when traversing from F0 to F1, 
     it calculates the corridor distance to the stairwell, adds the 3D staircase 
     incline distance (9.43m), and continues along the upper corridor.
   - Includes validation guards: prevents computing a route if you are already at 
     the destination (Same-Start guard), handles disconnected nodes, and returns 
     exact turn-by-turn waypoint lists.

3. 3D PROCEDURAL DIGITAL TWIN (THE GRAPHICS & ARCHITECTURE)
--------------------------------------------------------------------------------
Instead of importing a bloated, heavy 3D model that would take minutes to load in a 
browser, we built a high-performance procedural architectural generator in C# 
(BuildingVisualizer.cs).

A. Exterior Academic Facade (St. Paul's Block):
   - Realistic multi-storey academic block (52m length x 16m width x 12m height).
   - Solid warm off-white and light-grey concrete wall materials.
   - Terracotta facade accent bands running horizontally between each floor.
   - Neatly aligned horizontal window strips with blue-tinted glass and white mullions.
   - Main entrance portico with canopy columns, glass double doors, and roof signage.

B. Campus Environment & Lighting:
   - Daylight sunny campus atmosphere with a custom bright skybox and soft horizon fog.
   - Lush green turf lawn (160m x 140m), concrete plinth base, and stone entrance plaza.
   - 15 procedural shade trees with natural wood trunks and layered green canopies.
   - Balanced directional sunlight (intensity 1.15) and soft ambient fill (0.48) to 
     prevent pure-white glare.

C. 18 Fully Furnished Destinations across 3 Floors:
   - Ground Floor (F0):
     * Main Entrance: Security reception desk and digital kiosk.
     * CSE Office: HOD executive desk, ergonomic chair, visitor seating, tall bookcases, meeting table.
     * Student Lounge: Modular sectional sofas, coffee table, upholstered benches.
     * CSE Lab 1: Dual modular workbenches, 8 desktop computer monitors, instructor station, whiteboard.
     * Conference Room: Large boardroom table, 8 executive chairs, wide presentation screen.
   - First Floor (F1):
     * Classrooms 101 & 102: Teacher podiums, whiteboards, tiered student study desks and benches.
     * CSE Lab 2 (Networks): Server rack cabinet, dual workstation benches, monitor arrays.
     * Faculty Room 1: 4 faculty cubicles with divider partitions, desks, and task chairs.
     * Tutorial Room 103: Collaborative U-shaped seminar tables and tutor desk.
   - Second Floor (F2):
     * Classrooms 201 & 202: Teacher podiums, whiteboards, student desks.
     * CSE Lab 3 (AI & Cloud): Compute server tower, wide workstation benches, dual monitors.
     * Seminar Hall: Raised presentation stage, podium, wide projector screen, tiered auditorium seating.
     * Project Lab: Electronic hardware work islands, benchtop test equipment, component storage.

D. Precision Staircase Engineering:
   - Fixed the common issue of floating or misaligned stairs.
   - Flight 1 ascends from Y = 0.06m to Y = 4.06m (flush with First Floor slab).
   - Flight 2 ascends from Y = 4.06m to Y = 8.06m (flush with Second Floor slab).
   - Each flight features:
     * Solid structural concrete soffit slab.
     * 16 closed-riser steps with contrasting treads and riser faces.
     * Dual architectural handrails with vertical support posts.
     * Safety well guardrails and side catwalks connecting to corridors.
     * Architectural corridor sign badges.

E. Elevated Room Signage & Badges:
   - Room nameplates are mounted at Y = node.y + 3.05m with a 0.32m forward offset.
   - Sits cleanly in corridor open air above 2.6m walls and 2.2m door lintels.
   - Crisp white bold text backed by dark badges with floor-coded accent strips 
     (Emerald for F0, Sky Blue for F1, Amber for F2).

4. CAMERA & USER INTERACTION (ORBIT, PAN, ZOOM, COLLAPSE)
--------------------------------------------------------------------------------
Implemented in OrbitCamera.cs and NavigationUIController.cs:

A. 3D Viewport Controls:
   - Left-Click + Drag: Smooth 360-degree orbit around the building.
   - Right-Click + Drag (or Alt + Left-Click): Smooth panning.
   - Scroll Wheel: Smooth zoom in and out (clamped between 10m and 100m).
   - Input Latching: Mouse dragging is latched so the camera never stutters or 
     gets hijacked when dragging near UI elements.

B. Collapsible Navigation Sidebar:
   - A docked toggle button ('<' / '>') on the sidebar edge allows collapsing 
     the destination list into a clean, full-width architectural view.
   - When collapsed, the camera automatically glides to the center of the building 
     (X = 24m) and frames the entire campus. Clicking '>' restores the directory.

C. Tiered Floor Cutaway System:
   - Examiners often want to look inside the ground floor or first floor without 
     the upper slabs and roof blocking the view.
   - The top toolbar provides: "F0 Ground", "F1 First", "F2 Second", and "Full Building".
   - Clicking "F0 Ground" hides Floors F1, F2, upper walls, and upper stair flights.
   - Clicking "Full Building" immediately restores the solid exterior academic facade.

--------------------------------------------------------------------------------
5. NAVIGATION SIMULATION & ROUTE GUIDANCE
--------------------------------------------------------------------------------
Implemented in RouteVisualizer.cs:
- When a user selects a destination:
  1. Pathfinder calculates the Dijkstra route.
  2. A vibrant 3D path line (0.35m width) is drawn through the corridors and up stairs.
  3. Green sphere at the start, blue spheres at waypoints, and a pulsing red sphere 
     with a bobbing floating beacon at the destination.
  4. A bright glowing user avatar cone marks the current position.
- "Step Forward" button: Manually steps the user marker from waypoint to waypoint.
- "Auto Simulate" button: Automatically marches the user marker along the path 
  at 1.8-second intervals, gliding the camera smoothly along the route.
- "Back / Change": Cancels the active route and cleanly resets the view.
- Arrival Detection: When the destination is reached, an arrival card appears showing 
  the destination name, department, floor level, total distance traversed, and an option 
  to navigate to another room.

7. HOW TO LAUNCH AND DEMONSTRATE (STEP-BY-STEP)
--------------------------------------------------------------------------------
If you want to run the project right now on your machine:

1. Open PowerShell / Terminal in the project directory:
   cd "C:\Users\s karthik sriram\Desktop\projects\ar vr classroom\SmartClassroomAR"

2. Start the local WebGL server:
   python -m http.server 8080 --directory "Builds/WebGL/SmartClassroomAR_WebGL"

3. Open your browser (Chrome, Edge, or Firefox) and navigate to:
   http://localhost:8080/index.html

4. Live Demo Sequence for Examiners:
   a. Show the Full Building: Orbit with left-click, zoom with scroll wheel, pan with right-click.
   b. Show Full-Width Mode: Click the '<' arrow on the sidebar to collapse it into 
      presentation mode. Click '>' to open it again.
   c. Demonstrate Ground Floor Route: Click "CSE Department Office" -> Click "Step Forward" 
      to walk to the office -> Show the Arrival Card.
   d. Demonstrate Multi-Floor Navigation: Click "Navigate to Another" -> Select "Room 101" 
      (First Floor) -> Click "Auto Simulate" -> Watch the user marker walk down the corridor, 
      climb the 3D staircase, and arrive at Room 101.
   e. Demonstrate Floor Cutaways: Click "F0 Ground", "F1 First", "F2 Second" in the top 
      toolbar to show how you can inspect interior classrooms and labs without roof obstruction.
   f. Developer Diagnostics: Press 'D' on your keyboard to toggle the technical HUD 
      showing FPS, node count, and graph metrics.
